L1：语法错误 / 逻辑 Bug / 边界条件

#严重度文件行问题描述
1P0content.js95-120inlineCode+strikethrough/underline 组合被截断：inlineCode 分支（L95-104）return text 后，L120 `strikethrough` 和 L124 `underline` 永远不会被执行。若飞书数据中同时有 inlineCode+strikethrough，删除线丢失。
2P0content.js140-143背景色标记在 inlineCode 中语义错误：L142 `==text==` 用于高亮，但若 text 已被 inlineCode 包裹为 `...`，高亮标记 `==` 无效且在 HTML 中显示为字面量。
3P0content.js96inlineCode+粗体+链接组合丢失：若元素同时有 link.url + inlineCode + bold，L90 链接先处理，L96 inlineCode 覆盖为 HTML 标签，但链接 URL 信息已并入 text，在 <code> 内不再是有效 Markdown 链接。
4P0content.js870-871代码块内空行被全局正则破坏：`/\n{3,}/g` 和分割线正则作用于整个 markdown 输出，会错误压缩代码块（```...```）内的多空行和包含 --- 的行。
5P0content.js326,336depth>4 嵌套层级压扁：bullet 和 ordered 缩进使用 `Math.min(ctx.depth, 4)`，超过 4 层的嵌套内容被压到同一层级，丢失语义层级。
6P0content.js435-437table 单元格 Markdown 转义破坏代码：单元格内所有 `\` `|` `*` 等字符被无条件转义，若单元格内含 Markdown 代码标签（如 `inline code`），反引号会被转义为 `\``，破坏语义。
7P0content.js195-205getPlainText 遗漏元素类型：仅处理 textRun/mentionDoc/mentionUser，遗漏 mentionDate、inlineEquation、emoji、链接等类型，导致代码块/表格纯文本提取内容不完整。
8P0content.js861processBlock 顶层调用不传 path：L861 调用 `processBlock(..., 0, {}, prevSiblingType)` 未传 path 参数，使用默认 `new Set()`。若顶级 block 存在循环引用（如飞书 API 数据异常），无法检测。
9P0content.js332-337ordered 列表计数器跨深度污染：`ctx.counter[depth]` 在不同子树间共享同一个 counter 对象。若 block A 有 ordered 子项和 block B 有 ordered 子项同深度，计数器会相互干扰。
10P1content.js368callout 多行内容丢失引用格式：仅第一行加 `> ` 前缀，多行 callout 内容的后续行无引用前缀，Markdown 渲染时失去引用块视觉连续性。
11P1content.js483todo assignee 空检查不完整：`block.data?.todo?.assignee?.name` — 若 assignee 为 null，`assignee?.name` 返回 undefined，`|| ''` 回退正确。但若 assignee 为空对象 `{}`，assignee.name 返回 undefined，回退也正确。无实际 bug。
12P1content.js626-636_default 未知块类型的 children 递归依赖外部：`_default` 返回空字符串，依靠 processBlock 的外部递归处理 children。但若 _default 用于根级未知块，children 中的内容会丢失层级的缩进/容器语义。
13P1content.js716_convertOpts 无错误重置：convertDoc 没有 try-finally 来重置 _convertOpts，如果转换中途抛出异常，下次调用可能残留旧选项。L716 设置 _convertOpts，无 finally 清理。
14P1popup.js336downloadMarkdown 文件名含路径分隔符：`currentTitle` 可能包含 `/` 或 `\`，直接拼接为文件名会导致下载到子目录或失败。
15P1popup.js382ZIP 图片 fetch 无超时：`fetch(img.url, { mode: 'cors' })` 无 AbortController/超时，网络慢时可能永久挂起。
16P1popup.js593DOCX 导出文件名未清洗：`${currentTitle}.doc` 直接使用 title，含特殊字符时可能导致文件保存失败。
17P1background.js164dataUri 中日文文件名编码问题：`encodeURIComponent(content)` 对大文件可能正确，但 `data:...charset=utf-8,...` 编码后的中文内容在某些系统上下载时会乱码。
18P1content.js798-799block_sequence 去重使用 O(n) Set lookup：每个 ID 检查 `seqIds.has(id)`，大文档（数千 block）累积开销显著，但 Set 查找是 O(1)，实际无需优化。排查后无问题。
19P2content.js15-32LANG_ALIAS 有 14 个自身映射：java→java, rust→rust 等冗余条目消耗内存且无功能意义。
20P2content.js40-41FEISHU_COLORS 有 2 组重复颜色值：grey/gray 相同，cyan/teal 相同。
21P2content.js179emoji 回退链过长：`el.emoji?.text || el.text || ''` — 第二个 `el.text` 来源不明（可能是继承属性），应显式用 `el.emoji?.text`。
22P2content.js387-391table header_row 解析多重逻辑：同时支持 boolean 和 number，但飞书 API 文档未明确是否返回 number，兜底正确但可简化。
23P2content.js868markdown.trim() 丢失首尾有意义空白：文档开头或结尾有意保留空行的场景会被 trim 掉。

L2：鲁棒性 / 异常处理 / 边界条件

#严重度文件行问题描述
24P0content.js1009-1031消息监听器无超时保护：`convertDoc(opts)` 可能耗时 10+秒，若 popup 已关闭且 background 已清理，sendResponse 调用无效且可能导致扩展上下文失效。
25P0background.js72-126start_conversion 无超时机制：`chrome.tabs.sendMessage(tabId, ...)` 可能永久挂起（tab navigated away 但未关闭），无超时回退。
26P0content.js729-829mergedBlockMap 无大小限制：飞书 API 返回的 block_map 可能极大（恶意/异常文档），mergedBlockMap 无限增长可能导致内存溢出。
27P0content.js898-926injectUI innerHTML 拼接未经转义：popup.html 和 content script 的 UI 注入使用 innerHTML，无 CSP nonce 保护。
28P1content.js839-848跨页引用占位 ID 冲突：若 mergedBlockMap 中某 key 恰好等于 `uid.slice(-8)`，新插入的占位 block 会覆盖原有数据。
29P1content.js786飞书 API 错误 code=0 时处理不完整：L786 `json.code !== undefined && ... !== 0` 已修复 null 问题。但若 json.code === 0 但 data 为空/缺失，后续 pageData 可能为 undefined 导致崩溃。
30P1content.js790-792pageData 提取失败无保护：`json.data?.page || json.data` — 若两者均为 undefined/null，blockMap 和 blockSeq 为空，无错误提示静默输出空文档。
31P1content.js729mergedBlockMap 多页合并使用 Object.assign：若不同页返回相同 block ID（飞书 API 异常），后页数据静默覆盖前页，无冲突检测或警告。
32P1popup.js266-331轮询退避策略缺失：pollConversion 固定 1 秒间隔，若 background 持续无响应（SW 已终止），每秒发送消息浪费资源且无超时后降级处理。
33P1popup.js395split+join URL 替换为 O(n²) 复杂度：`markdown.split(img.url).join(...)` 对大 Markdown（>1MB）和大量图片（>50 张）时，每次 split+join 扫描全文，复杂度 O(m*n)。
34P1popup.js429ZIP 压缩级别固定 level:6：大文档（>5MB）和大量图片时 ZIP 生成可能占用过多 CPU 导致 popup 页面无响应。应提供降级选项或 chunk 处理。
35P1popup.js291-292轮询中 resp 可能为 undefined：`resp.status` — 若 sendMessage 返回 undefined（SW 未响应），访问 resp.status 会 throw TypeError。
36P1popup.js833-841pagehide 保存可能失败无回调：`chrome.storage.local.set(...)` 无错误处理，存储空间满或权限问题时静默丢失数据。
37P1background.js17-24getTasks/saveTasks 竞态条件：若两个异步操作同时读写 tasks，后写覆盖前写。典型场景：start_conversion 和 cleanupOldTasks 同时执行。
38P2content.js257-259getApiEndpoint 未支持所有 URL 类型：bitable 类型已解析但 getApiEndpoint 不支持，会静默兜底到 space API。
39P2content.js738maxPages 硬编码为 20：无法通过 options 调整，超大型文档（如 wiki 知识库）可能截断过多。
40P2popup.js819-823恢复上次结果未检查数据完整性：直接从 storage 恢复 markdown/title/imageUrls，可能因 storage 损坏而恢复不完整数据。
41P2content.js931-981UI 按钮点击无防抖：快速双击可能导致多次转换并发执行，statusEl 状态混乱。
42P2popup.js337-352downloadMarkdown 回退下载无错误提示：background 下载失败后回退到 popup 内下载，但无任何用户可见的状态反馈。
43P2background.js44-55cleanupOldTasks 无错误恢复：若 storage.local 读取失败（如 storage 损坏），整个清理流程中断且不会重试。

L6：性能优化

#严重度文件问题描述
127P0popup.jsZIP 图片下载 O(n)×O(m) 复杂度：每张图片的 split+join 操作扫描整个 markdown 文本（L398），100 张图片×1MB 文档 = 100MB 字符串操作，可导致 popup 冻结。
128P1content.jsrenderRichText 无缓存：同一 block 可能被多次渲染（如跨页引用），每次重新遍历 elements 数组。
129P1content.jsprocessBlock 递归无 memoization：同 block ID 可能在多处分叉引用，重复解析。
130P1content.jsmergedBlockSeq 遍历中 Set.has+Set.add 重复：L857 `if (seen.has(blockId))` + L858 `seen.add(blockId)` 在循环中执行，对数千 block 产生额外开销。
131P1content.js表格解析中 `Math.max(...rows.map())` 可能导致大量参数传递。
132P1popup.js历史记录渲染 innerHTML 使用字符串拼接，大历史（20 条）无虚拟列表。
133P1popup.jsZIP 分批并发为固定 5 并发，未根据网络/CPU 动态调整。
134P1content.jsObject.assign(mergedBlockMap, blockMap) 逐页合并大对象，对超大型文档 Object.assign 可能是瓶颈。
